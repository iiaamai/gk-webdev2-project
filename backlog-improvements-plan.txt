M. Customer payment visibility (SHIPPED IN CODE — Nov 2026)
======================================================================
Locked via /clarify (Nov 2026).

Goals
- Show **Paid / Unpaid** on **active** booking cards (customer home + My Bookings Active tab).
- Add a **4th home KPI** for count of bookings with **unpaid** invoices.
- Surface a **5-day payment window** from booking creation (UI only — no enforcement).

----------------------------------------------------------------------
M1. Paid / Unpaid chip (active bookings only)
----------------------------------------------------------------------
| Surfaces | Customer **home** → Active bookings grid · **My Bookings → Active** tab |
| Component | `resources/views/components/customer/booking-card.blade.php` (shared) |
| Out of scope | History tab cards · booking **detail** page header chip |

Chip rules (simple — from `invoice.status` only)
| Invoice | Chip |
|---------|------|
| `paid` | **Paid** (success tone — `InvoiceStatus::badgeTone()`) |
| `unpaid` | **Unpaid** (warning tone) |
| No invoice row | **No chip** |

No separate chips for payment proof pending/rejected in this slice.

Ensure queries eager-load `invoice` where cards render (already on overview + index active list).

----------------------------------------------------------------------
M2. Homepage 4th KPI — unpaid bookings
----------------------------------------------------------------------
| Placement | Fourth summary card beside Pending / In progress / Completed |
| Label | e.g. **Unpaid** |
| Count | Customer’s bookings with **`invoices.status = unpaid`** (any trip status — includes completed-but-unpaid unless changed at implement time) |
| Optional | Subtitle with total PHP due (parity with admin unpaid KPI) |

Backend: extend `App\Services\CustomerOverviewQuery::gather()` → e.g. `unpaid_count`, optional `unpaid_total`.

View: `resources/views/portals/customer-home.blade.php` — grid layout for four KPIs.

----------------------------------------------------------------------
M3. Five-day payment window (UI only)
----------------------------------------------------------------------
| Start | **`booking.created_at`** calendar date in **Asia/Manila** |
| Due | End of **day 5** after creation — show **“Due by M j, Y”** on active card while invoice is unpaid |
| Overdue | After due date, still unpaid → **“Overdue”** copy/styling on card |
| Paid | No due/overdue messaging |

**No enforcement in this slice:** no auto-cancel, no block on new bookings, no staff-only flags, no scheduled jobs.

Suggested helper: e.g. `App\Support\PaymentDue` — `dueDate(Booking)`, `isOverdue(Booking)` (unpaid + past due).

----------------------------------------------------------------------
M4. Tests (suggested)
----------------------------------------------------------------------
- Overview query returns correct `unpaid_count`.
- Booking card renders Paid/Unpaid when invoice loaded.
- Due/overdue copy for fixed `created_at` + unpaid invoice (feature test or unit on helper).

M5. Docs follow-up (optional with slice)
