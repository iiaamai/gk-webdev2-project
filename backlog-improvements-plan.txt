A. Driver Time-In / Time-Out (SHIPPED — reference)
======================================================================
Implemented in codebase (Staff Drivers page, login gate, seeder, tests). Render/local QA done.

Process (summary)
- Office (Staff or Admin) records Time-In → driver may log in.
- Office records Time-Out → driver cannot log in until timed in again.
- Driver “requests” are offline only (no in-app buttons).

Locked at first ship
| Topic | Decision |
| When | MVP / checkpoint B |
| Who records | System Admin + Staff |
| No attendance record yet | Login denied until first Time-In |
| Time-Out during trip | Block if driver has accepted or in_transit booking |
| Same calendar day | Unlimited Time-In / Time-Out cycles |
| Driver registration | No auto-login; redirect to login with office message |

Deploy note
- Run migration + DriverAttendanceSeeder (or manual Time-In) on each environment so demo drivers can log in.

Gap vs later slices (B, C, E–G below)
- Admin has no dedicated **Drivers** list route/nav (only User profile + staff-style list missing on admin).
- Time-out did not end active driver sessions (superseded by slice C).

Fleet (settled — not backlog)
- **Staff**: in-use vehicles — limited edit UI (status/driver/details locks on edit).
- **Admin**: **full override** while in use (edit all fields, status/driver, archive) — unchanged; Slice D dropped.

C. Time-Out ends active driver session (PLANNED — policy change)
======================================================================
Status: design agreed (clarify) — **replaces** shipped rule “new logins only”.

New rule
- When office records **Time-Out**, any **existing driver portal session** must end.
- On the driver’s **next HTTP request**: middleware detects not timed in → logout, invalidate session,
  redirect to login with a clear message (e.g. timed out by office).
- **Middleware on all `driver/*` routes**: must be timed in (covers login gate + portal).

When building
1. `EnsureDriverTimedIn` (or equivalent) on driver route group.
2. Update TimeOutDriver / docs; remove “session unchanged” behavior from tests.
3. Replace test `test_time_out_does_not_log_out_existing_driver_session` with
   “next request after time-out → guest + login”.
4. Update this backlog section and permissions_matrix if needed.

Out of scope (unchanged)
- Stop GPS / kill WebSocket on time-out as a separate product slice (session end is enough for v1).

Suggested bundle
- Implement **B + C** together (one PR / one deploy).

F. Multi-trip pricing when cargo exceeds one load (PLANNED)
======================================================================
Status: design agreed (clarify) — **supersedes** shipped “block over capacity; choose larger type”
for customer create (see slice G for who must enter cargo).

Goal
- One booking still uses **one selected pricing / vehicle type**.
- If cargo weight needs more than one full load at that type’s capacity, **invoice amount** reflects
  multiple trips at the **list fare** for that type.

Locked formula
- `trips = max(1, ceil(cargo_kg ÷ pricing.capacity_kg))`
- `invoice_amount = trips × pricing.amount` (snapshot on booking/invoice at create time; same pattern
  as today’s pricing snapshot — confirm in CreateBookingInvoice / booking payout fields when building).

Behavior change vs today
- **Remove** validation error that blocks `cargo_kg > capacity_kg` on customer create.
- **Show** customer-facing hint when trips > 1 (e.g. estimated trips and total before submit).
- Staff/Admin flows that capture cargo must use the **same formula** when creating/updating bookings (slice G).

When building
1. Centralize trip count + amount in a small helper/service (avoid duplicating ceil logic).
2. Update `CreateCustomerBooking`, `CreateBookingInvoice` (and Staff/Admin store/update paths).
3. Update `StoreBookingRequest` / any Form Requests — drop hard fail on over-capacity; validate cargo_kg ≥ 1.
4. Tests: 1500 kg on 1000 kg capacity → 2 × fare; 500 kg on 1000 kg → 1 × fare; edge ceil boundaries.
5. Update docs: features.txt or lifecycle if invoice on multi-trip is documented for customers.

Suggested bundle
- Implement **F + G** together (one PR).
