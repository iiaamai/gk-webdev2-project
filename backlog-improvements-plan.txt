H. Capacity booking — multi-trip request at pickup (SHIPPED)
======================================================================
Status: shipped (Nov 2026).

Summary:
- Invoice at create = **1 × list fare**.
- After **arrived_at_pickup**: customer one round-trip request → office approve/reject
  (reject **cancels**) → customer confirm if count changed → driver accept →
  invoice = `approved_round_trips × fare` + wrong-truck fee when applicable (QA-3 fixed in I).
- Customer **change vehicle type once** at pickup; fee = Settings `wrong_truck_fee_percent`.
- Round trip = pickup → dropoff → return to pickup.

Open follow-up:
- None (QA-4 addressed in I-b).

I. Booking lifecycle — statuses, stepper, EIR/POD timing (SHIPPED)
======================================================================
Status: shipped + amended (Nov 2026). Locked via /clarify (original I + haul split).

Problem solved
- Single **in_transit** conflated “to pickup” and “haul after pickup”.
- Driver EIR/POD gated to **transit_completed**; complete requires EIR + POD.

----------------------------------------------------------------------
Target status enum (bookings.status)
----------------------------------------------------------------------
pending | accepted | transit_to_pickup | arrived_at_pickup | in_transit |
transit_completed | completed | cancelled

Happy path
  pending → (gatepass, still pending) → accepted → **transit_to_pickup**
  → **arrived_at_pickup** → **in_transit** (haul) → **transit_completed**
  → (driver EIR + POD) → **completed**

Stepper (UI)
  Pending → Gatepass → Accepted → To pickup → At pickup → Haul → Transit done → Completed

----------------------------------------------------------------------
Locked decisions (amended I)
----------------------------------------------------------------------
| Topic | Decision |
| transit_to_pickup | New status: en route **to** pickup (driver: “Mark transit to pickup” from accepted) |
| arrived_at_pickup | Same rules as before: timestamp, multi-trip, vehicle change |
| in_transit | Reused enum value = **haul in progress** only (after pickup; badge “Haul in progress”) |
| Multi-trip gates | Block **transit_completed** and **completed** only — **not** entering haul |
| Driver EIR/POD | **transit_completed** only; complete requires both |
| Staff/Admin EIR/POD | Unchanged (non-cancelled bookings) |
| Migration | `in_transit` without `arrived_at_pickup_at` → **transit_to_pickup** |

----------------------------------------------------------------------
Process flow (reference)
----------------------------------------------------------------------

  [Create] pending, invoice 1× fare
      → gatepass (still pending)
      → driver accept → accepted
      → driver Mark transit to pickup → transit_to_pickup
      → driver Arrived at pickup → arrived_at_pickup
            ├─ optional: vehicle type once (+ fee)
            ├─ optional: round-trip request → office / customer / driver steps
            │     → office reject → cancelled
      → driver Start haul → in_transit
      → driver Transit completed → transit_completed
            → driver EIR + POD
      → driver Mark completed → completed

----------------------------------------------------------------------
QA checklist (Slice I — regression)
----------------------------------------------------------------------
- accepted: Mark transit to pickup only; no EIR/POD.
- transit_to_pickup: Arrived at pickup; no EIR/POD; no Mark completed.
- arrived_at_pickup: customer multi-trip / vehicle type; Start haul; no EIR/POD.
- in_transit (haul): Mark transit completed (blocked if multi-trip open); no EIR/POD.
- transit_completed: EIR/POD; Mark completed when both exist.
- completed: terminal; receipt rules unchanged.
- Multi-trip approve preserves wrong-truck fee on invoice.

J. Round-trip lap progress during haul (SHIPPED)
======================================================================
Status: shipped (Nov 2026 — /clarify + /implement).

Behavior
- When office-approved **N > 1** and multi-trip is resolved, during **in_transit** the driver marks
  each lap (**1/N … N/N**), then **Transit completed → EIR/POD → Completed**.
- **N = 1:** no lap UI; haul → transit completed unchanged.
- **Transparency:** `bookings._round_trip_laps` banner (large X/N + progress bar) on customer,
  driver, staff, and admin **booking show** only (not list rows).
- Driver action in **Next step:** “Mark round trip complete (X of N)”.
- Transit completed blocked until **N/N**; laps reset to 0 when haul starts.

Code
- `multi_trip_laps_completed` on bookings; `MarkRoundTripLapComplete`; `BookingMultiTrip` helpers;
  `BookingPolicy::markRoundTripLapComplete`; route `driver.deliveries.round-trip-lap.complete`.
- Tests: `tests/Feature/RoundTripLapProgressTest.php`; S2/S3 in `ScenarioQaReportTest` mark all laps.

Out of scope (J unless added later)
- Geofence per lap; undo lap; customer/office increment; per-lap invoice lines.

QA checklist (Slice J)
----------------------------------------------------------------------
