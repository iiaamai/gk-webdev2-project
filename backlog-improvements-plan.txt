L. Metric tons UI + customer cancellation (SHIPPED IN CODE — Nov 2026)
======================================================================
Locked via /clarify (Nov 2026).

Goals
- Show weight/capacity in **metric tons** everywhere users see it (DB stays kg).
- Let customers **cancel** more of the trip lifecycle with a clear **10% cancellation fee** rule set.
- Align **admin** late-cancel fee with the same **10%** (replace today’s 25% in `CancelBooking`).

----------------------------------------------------------------------
L1. Metric tons (display + forms only)
----------------------------------------------------------------------
| Rule | Keep `capacity_kg`, `cargo_kg`, and validation in **kg** in the database |
| Display | **1 metric ton = 1,000 kg** (e.g. 42,000 kg → **42 tons**) |
| Forms | User enters **tons**; convert to kg on save; convert back for edit/display |
| Surfaces | Marketing/pricing, booking create/edit, fleet & pricing admin, receipts/PDF, emails, vehicle-type dropdown copy (“X tons max”), trip detail read-only fields |

Do **not** rename DB columns to tons in this slice.

----------------------------------------------------------------------
L2. Customer cancel — when the button shows
----------------------------------------------------------------------
Show **Cancel** on customer booking show when they own the booking and status is:

| Status | Cancel allowed |
|--------|----------------|
| pending (with or without gatepass) | Yes |
| accepted | Yes |
| transit_to_pickup | Yes |
| arrived_at_pickup | Yes |
| in_transit | Yes |
| transit_completed | **No** (hide button — POD/completion path) |
| completed / cancelled | No |

Confirm dialog must say whether cancel is **free** or **10% of current invoice** before submit.

----------------------------------------------------------------------
L3. Cancellation fee — 10% of invoice (customer + admin)
----------------------------------------------------------------------
| Fee rate | **10%** of the booking invoice **`amount` at cancel time** (includes multi-trip / wrong-truck adjustments already on the invoice) |
| Admin/staff late cancel | Same **10%** (change `CancelBooking` from 25% → 10%; invoice notes e.g. “Cancellation fee (10%).”) |
| When fee applies | Invoice is **replaced** with the fee total (**even if previously paid** — manual refund/process out of scope for MVP; document for ops) |

Customer fee matrix
|-------------------|------|
| Pending, **no gatepass**, cancel on **same calendar day** as **`created_at`** (Asia/Manila) | **Free** — invoice unchanged (full list fare remains) |
| Pending, **no gatepass**, cancel **after** that calendar day | **10%** — invoice replaced |
| Pending **with gatepass** (driver not accepted yet) | **10%** |
| **Accepted** or any in-progress status in L2 table | **10%** |

Side effects (unchanged pattern): status → `cancelled`, release vehicle/driver, emails + activity log (`late_cancel_fee` flag).

Implementation touchpoints (for dev)
- `BookingPolicy::cancel` — widen customer statuses; same-day free rule on `created_at`
- `CancelBooking` — customer fee logic; fee base = invoice amount; 10% rate for admin + customer
- `resources/views/customer/bookings/show.blade.php` — cancel UX + copy
- Tests: `BacklogImprovementsTest`, customer cancel tests, new same-day / gatepass / fee cases
